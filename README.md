# Vitrine

A curated, gallery-first directory of well-designed websites. Browse by category, tag or search, preview sites live inside the app on desktop, tablet and mobile viewports, and jump to the original site.

## Run it

```bash
npm install
npm run dev        # http://localhost:3000
npm run build      # production build (prerenders every /site/[slug] page)
```

## Stack

Next.js 16 (App Router, Cache Components), React 19, TypeScript, Tailwind CSS v4, Radix primitives in the shadcn/ui style, Lucide icons, Geist fonts.

## How it works

| Area | Where | Notes |
| --- | --- | --- |
| Data model | `src/lib/types.ts` | `Website`, `Category`, filter types. Framework-free, so it can mirror DB rows. |
| Seed data | `src/data/websites.ts`, `src/data/categories.ts` | Hand-curated entries. |
| Captured assets | `src/data/captures.json`, `public/screenshots`, `public/favicons` | Generated by `npm run capture`. |
| Data access | `src/lib/websites.ts` | Async functions (`getWebsites`, `getWebsiteBySlug`, …). Swap this file for Supabase or a CMS; components stay unchanged. |
| Filtering | `src/lib/filters.ts` | Pure functions: search, category, tag, view and sort. |
| URL state | `src/hooks/use-gallery-filters.ts` | Filters live in the query string (`?category=saas&tag=dark&q=…&sort=popular`). Updates use the History API, so filtering never hits the server. |
| Favorites | `src/hooks/use-favorites.ts` | `localStorage`-backed and synced across tabs. Ready to swap for account-backed collections. |
| Gallery | `src/components/gallery/*` | `GalleryView`, `WebsiteCard`, `SiteThumbnail`, `FilterControls`. |
| Sidebar | `src/components/sidebar/*` | Sticky on ≥1024px, drawer below. |
| Preview | `src/components/preview/*` | `SitePreview`, `PreviewToolbar`, `WebsitePreview`, `ResponsivePreviewFrame`, `SiteInfoPanel`. |
| Embed check | `src/app/api/embed/[slug]/route.ts` | Reads `X-Frame-Options` and CSP `frame-ancestors` (cached hourly) to decide between a live iframe and the screenshot fallback. It only detects restrictions and never bypasses them. Accepts a slug, not a URL, so it can only probe curated sites. |

### Preview behaviour

1. The full-page screenshot paints immediately, dimmed.
2. `/api/embed/:slug` checks whether the site allows framing.
3. If it does, a sandboxed iframe loads at the device's real CSS width (desktop fills the canvas; tablet is 820px; mobile is 390px). On small screens the frame is zoomed out to fit.
4. If framing is blocked, the screenshot stays, with a notice and an **Open website** button. If loading takes more than 12s, a toggle offers the screenshot.

Keyboard: `/` or `⌘K` to search · `Esc` to close the preview · `1` `2` `3` for desktop, tablet and mobile · `←` `→` for the previous and next site · `I` for details.

## Adding a website

1. Append an entry to `src/data/websites.ts`.
2. Run `npm run capture -- <slug>`. This uses your local Google Chrome through `playwright-core` (set `CHROME_PATH` to override). It saves a 1280×800 card image, full-page desktop and mobile screenshots, a favicon, the OG image URL and an embeddability hint.
3. Check the screenshot. Bot walls and pop-ups sometimes need a re-capture or a different site.

`npm run capture -- --all` recaptures everything.

## Next steps

The structure leaves room for these, none of which is built yet:

- Admin dashboard and a submission form. Write to the same `Website` shape and replace `src/lib/websites.ts` with DB queries.
- Automatic OG extraction and screenshot generation. Run `scripts/capture.mjs` as a job (queue or cron) and store the output in object storage.
- User accounts, collections and bookmarks. Replace the store in `use-favorites.ts`.
- Trending and featured sections. `featured` and `viewCount` already exist on every entry.
